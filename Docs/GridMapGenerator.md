# 새 타일 맵 생성기 사용법

`AUCGridMapGenerator`는 기존 `AUCMapGenerator`와 독립적으로 사용합니다. 생성 결과는 정수 타일 좌표를 사용하며, 방과 복도를 만든 뒤 모든 제약을 다시 검사합니다. 실패한 후보는 레벨에 적용하지 않습니다.

## 에디터에서 시작합니다

1. 레벨에 `UCGridMapGenerator` Actor를 배치합니다. 위치는 변경할 수 있으며 회전은 0, 스케일은 1로 설정합니다.
2. Details의 `변수|생성 → Settings`에서 설정을 변경합니다.
3. `Generate Map`으로 `Generation Seed`를 재현하거나, `Generate Random Map`으로 새 시드를 생성합니다.
4. `Validate Random Seeds`로 새 맵을 `Validation Runs`회 생성하고 검사합니다. 기본은 100회이며 10회, 1000회 등으로 변경합니다.
5. `Last Report`와 Output Log에서 성공·실패 횟수, 최초 실패 시드, 소요 시간을 확인합니다. 실패 시드를 `Generation Seed`에 복사하면 재현합니다.

검증은 Actor를 반복 생성하지 않고 데이터만 생성하므로 현재 표시한 맵을 유지합니다. 진행 창에서 취소하면 완료한 횟수까지 보고합니다. 취소는 현재 시드의 제한된 탐색이 끝난 다음 처리합니다.

## 설정의 단위를 확인합니다

| 설정 | 의미 |
|---|---|
| Map Size | X는 가로, Y는 세로 타일 개수로 설정합니다. 좌표는 0부터 시작합니다. |
| Tile Size | 타일 중심 간 월드 거리(cm)를 설정합니다. |
| Min / Max Rooms | 사전 제작 방을 포함한 전체 방 개수 범위를 설정합니다. 같은 값이면 정확한 개수를 생성합니다. |
| Min / Max Room Size | 랜덤 직사각형 방의 X·Y 길이 범위를 설정합니다. |
| Min / Max Connections | 서로 다른 방과의 직접 연결 수를 설정합니다. 기본 구현은 랜덤 방의 변마다 하나씩 최대 4개 연결을 지원합니다. |
| Extra Connection Probability | 최소 연결을 충족한 후 추가 복도를 시도할 확률을 설정합니다. 실제 추가 여부는 상한과 공간 조건을 함께 적용합니다. |
| Min Room Gap | 두 방의 사각형 사이에 최소 몇 칸의 빈 타일 띠를 확보할지 설정합니다. 대각선에서도 사각형의 여유 공간을 기준으로 판정합니다. |
| Min / Max Corridor Length | 방 내부 출입구 타일을 제외한 연결 통로의 최단 이동 타일 수를 제한합니다. 통로 확장 후에도 다시 검사합니다. |
| Max Corridor Width | 구간별 확장 목표 폭을 1~8타일로 설정합니다. 기본값은 3이며 공간이 부족한 부분은 한 칸으로 유지합니다. |
| Corridor Widening Probability | 각 구간을 넓힐 확률을 설정합니다. 기본값은 0.65로 설정합니다. |
| Min / Max Wide Section Length | 폭과 확장 방향을 다시 선택하는 구간 길이를 설정합니다. 기본값은 2~6타일로 설정합니다. |
| Room Side Passage Probability | 출입구에서 방의 일부 측면으로 길을 뻗을 확률을 설정합니다. 기본값은 0.6으로 설정합니다. |
| Max Room Side Length | 방 옆으로 뻗는 길의 최대 연장 칸 수를 설정합니다. 기본값은 6이며 0이면 별도 측면 연장을 생략합니다. |
| Max Layout Attempts | 한 시드에서 방 배치와 연결을 다시 시도할 최대 횟수를 설정합니다. |
| Placement Attempts Per Room | 한 후보 배치에서 각 방 위치를 시도하는 최대 횟수를 설정합니다. |
| Max Search Nodes | 한 시드의 모든 복도 탐색에 공통으로 적용할 방문 노드 한도를 설정합니다. |

방 1개는 최소 연결 수 1과 모순되므로 2개 이상을 사용합니다. 모든 방의 최대 연결 수가 1이면 방 2개만 허용합니다. 모든 방의 연결 수를 같은 홀수로 고정하려면 전체 방 개수도 짝수로 고정합니다.

14×20 타일의 작은 맵은 다음 설정으로 시작합니다.

```text
Map Size = (14, 20)
Min Rooms = 4
Max Rooms = 4
Min Room Size = (2, 2)
Max Room Size = (3, 3)
Min Connections = 1
Max Connections = 4
Min Room Gap = 2
Min Corridor Length = 1
Max Corridor Length = 40
```

## 메시와 소품을 배치한 방을 제작합니다

1. `UCDesignedRoom`을 부모로 하는 Blueprint Actor를 생성합니다. 예를 들어 `BP_TreasureRoom`으로 생성합니다.
2. Class Defaults에서 `Size`, `Authored Tile Size`, `Doors`, `Blocked Tiles`를 설정합니다.
3. Components에서 바닥·벽·소품 메시를 배치합니다. 회전은 생성 과정에서 적용하지 않습니다.
4. 생성기의 `Settings → Designed Rooms`에 이 클래스를 등록하고 `Count`를 지정합니다.
5. 보물방이라면 `Min Start Distance`를 설정합니다. `Max Start Distance = 0`이면 상한을 적용하지 않습니다.

`Count`는 필수 생성 개수이며 전체 `Min Rooms`에 포함합니다. 예를 들어 전체 방 8개 중 보물방 `Count = 1`이면 나머지 7개를 랜덤 방으로 생성합니다.

방 Actor의 원점은 **로컬 타일 (0, 0)의 바닥 중심**으로 설정합니다. 로컬 타일 `(X, Y)`의 중심은 `(X × TileSize, Y × TileSize, 0)`에 배치합니다. 기본 3×3 방, 200cm 타일이면 방 외곽은 각 축 -100cm부터 500cm까지입니다. 제작한 메시의 규격을 유지하기 위해 `Authored Tile Size`와 생성기의 `Tile Size`가 같아야 합니다. 방마다 바닥 메시도 직접 포함합니다.

출입구는 방 내부 경계 타일 `Tile`과 바깥쪽 단위 방향 `Outward`를 함께 지정합니다. 예를 들어 3×3 방의 왼쪽 중앙은 `Tile = (0, 1)`, `Outward = (-1, 0)`으로 지정합니다. 오른쪽 중앙은 `(2, 1)`, `(1, 0)`으로 지정합니다. 출입구 메시의 개구부는 해당 경계 중앙에 맞춥니다.

**사전 제작 방에 선언한 모든 출입구를 서로 다른 방과 연결합니다.** 연결되지 않은 구멍이 남지 않도록 출입구를 후보가 아닌 필수 연결로 취급합니다. 막다른 보물방은 출입구를 1개만 선언합니다. 이때 전체 `Min Connections`도 1이어야 합니다. 방의 크기를 바꾸면 기본 출입구 좌표도 함께 수정합니다.

`Blocked Tiles`에는 이동을 막는 소품이나 벽이 차지하는 로컬 타일을 지정합니다. 남은 이동 가능 타일과 모든 출입구는 방 내부에서 연결되어 있어야 합니다. 불규칙한 형태도 사각형 점유 범위 안의 막힌 타일로 표현하며, 다른 방이 해당 점유 범위 안으로 들어오지는 않습니다.

시작점은 거리 0을 허용하는 방 내부에서 선택합니다. 보물방 거리는 모든 추가 복도까지 완성한 뒤, 시작 타일부터 그 방에 최초 진입하는 타일까지의 최단 상하좌우 이동 횟수로 검사합니다. 시작점과 보물방의 직선거리를 사용하는 것이 아닙니다. 플레이어를 자동 이동시키지는 않으며 C++에서 성공한 `Generate(Seed)` 이후 `GetStartWorldLocation()`을 사용합니다.

## 연결과 실패 처리를 확인합니다

방을 배치한 후 서로 다른 그룹을 실제 복도로 연결하고, 부족한 연결 수를 채운 다음 추가 순환 경로를 시도합니다. 먼저 연결을 보장하는 한 타일 중심 경로를 만든 뒤 구간별 폭·길이·좌우 확장 비율을 무작위로 선택합니다. 길이 넓어지거나 다시 좁아지고, 출입구 일부에서는 방의 한쪽 옆으로 길을 연장합니다. 모든 방을 둘러싸는 고리나 고정된 여유 공간을 강제로 생성하지 않습니다.

확장은 이미 연결된 경로에 붙는 타일만 추가합니다. 서로 다른 복도의 교차·겹침·변을 맞댄 합류와 관계없는 방의 접촉을 금지합니다. 연결 대상 방의 벽 옆으로는 길을 확장할 수 있지만, 방 내부는 선언한 출입구로만 드나들도록 처리합니다. 따라서 측면 길 자체를 다른 방과의 추가 연결로 계산하지 않습니다. 대각선 접촉은 이동 연결로 계산하지 않습니다.

설정한 확장 폭은 각 구간의 목표 폭이며 회전부의 겹침이나 측면 연장까지 합친 전체 영역의 경계 상자를 제한하는 값은 아닙니다. 벽·기존 경로·맵 경계에 막히면 해당 부분의 확장만 생략합니다. 넓은 구간이 많기를 원하면 `Corridor Widening Probability`를 높이고, 방 주변 길을 줄이려면 `Room Side Passage Probability`를 낮춥니다. 기존 한 칸 통로는 `Max Corridor Width = 1`, `Room Side Passage Probability = 0`으로 설정합니다.

복도는 BFS로 출입구 조합별 최단 경로를 탐색합니다. 최단 경로가 최소 길이보다 짧으면 해당 조합을 제외합니다. 최소 길이를 채우려고 임의의 굴곡을 추가하지 않습니다. 따라서 해가 존재하는 설정이라도 휴리스틱 배치와 탐색 한도 때문에 생성에 실패할 수 있습니다. 실패 시 조건을 낮추거나 방 개수를 줄이지 않고 이유를 반환합니다.

성공한 결과에 대해서는 다음을 검사합니다.

- 맵 경계, 전체 및 사전 제작 방 개수, 랜덤 방 크기를 검사합니다.
- 방 사이 간격, 중복 방 연결, 출입구 재사용 및 복도 길이를 검사합니다.
- 중심 경로와 확장 타일의 연속성·겹침·고립, 의도하지 않은 방 접촉과 복도 합류를 검사합니다.
- 모든 이동 가능 방·복도 타일에 시작점에서 도달할 수 있는지 검사합니다.
- 사전 제작 방의 형태 및 시작점으로부터의 거리 조건을 검사합니다.

검증은 **선언한 타일 데이터와 출입구 경계**를 기준으로 수행합니다. 메시 충돌, 캐릭터의 캡슐 크기와 NavMesh까지 자동 검증하지는 않습니다. 소품 충돌은 `Blocked Tiles`와 일치시키고 문 폭은 캐릭터 크기에 맞춰 제작합니다. 랜덤 방과 복도는 기본 인스턴스 바닥을 제공하며, 랜덤 방의 외곽에는 출입구만 뚫린 경계 벽을 배치합니다. 벽 높이는 `Room Wall Height`로 설정합니다. 사전 제작 방은 직접 만든 벽·출입구를 사용합니다. 천장·장식은 별도로 추가합니다. `GetLayout()`의 각 연결에서 `Tiles`는 중심 경로, `ExtraTiles`는 추가된 바닥 타일을 제공합니다.

## 시각화와 결과 수명을 확인합니다

- 파랑: 랜덤 방을 표시합니다.
- 청록: 사전 제작 방을 표시합니다.
- 초록: 복도를 표시합니다.
- 빨강: 제작 방의 막힌 타일을 표시합니다.
- 분홍 화살표: 실제 사용한 출입구를 표시합니다.
- 노랑 구체: 시작점을 표시합니다.

`Debug Duration` 동안 디버그 선을 표시하며 `Draw Generated Map`으로 다시 표시합니다. 다른 시스템의 디버그 표시를 지우지 않으므로, 연속 생성 시 이전 선은 수명이 끝날 때까지 함께 표시합니다. `Clear Generated Map`은 이 생성기의 바닥과 제작 방만 제거합니다. 생성 결과는 미리보기 및 런타임 데이터이며 레벨 베이크 기능을 제공하지 않습니다. 저장한 설정과 시드로 다시 생성합니다.

## 자동 테스트를 실행합니다

Session Frontend의 Automation에서 `Uncovered.GridMap`을 실행합니다. 기본 시드 배치 검사, 14×20 크기, 결정적 재현, 불가능한 조건, 손상 데이터, 사전 제작 방과 거리 조건, 순환 경로, 불규칙한 확장 통로와 방 벽 우회 거리, Actor 배치와 정리를 검사합니다.

맵 크기는 축별 최대 512타일, 방 개수는 최대 128개, 에디터 반복 검증은 최대 10000회로 제한하여 실수로 과도한 작업을 시작하지 않도록 설정합니다. 생성 시간은 배치 밀도와 거리 제약에 따라 달라지므로 `Last Report`의 실제 측정값을 확인합니다.
